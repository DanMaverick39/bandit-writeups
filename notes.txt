How I solved it: So following up from the specifications task the file was now owned by a user, and also a group, and was 33 bytes in size, so to find the user I used find / -user bandit7 -group bandit6 -size 33c. Now it's interesting to note that '/' after find means search this whole machine, literally everywhere, and alo every file has two owners, a user and a group, it's a simple concept to grasp, like a student and a department. In a school not every department has unlimited access, but the students in a department have unlimited access. that's not all, I was receiving some message errors and cleared it by using 2>/dev/null which meant that 2>/dev/null — This is redirection. Remember > sends output somewhere? Well Linux has two types of output:

Standard output (1) — normal results
Standard error (2) — error messages

2> means "redirect error messages." /dev/null is a special black hole on Linux — anything sent there disappears permanently.
So 2>/dev/null means: "throw all error messages in the bin, show me only real results."
You'll use this constantly in security work to filter noisy output. 
So basically I was saying: 
"Search the entire filesystem for files owned by user bandit7, belonging to group bandit6, exactly 33 bytes in size — and hide all permission errors."
